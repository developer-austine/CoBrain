┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                      LAYER 3: PROCESSING PIPELINE (Python)                                    │
│                                                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────────────────────────────────────┐ │
│  │  Celery Worker (Docker Container: "worker")                                                            │ │
│  │  commands/ingest.py                                                                                    │ │
│  │  ═══════════════════════════════════════════════════════════════════════════════════════════════════ │ │
│  │                                                                                                         │ │
│  │  run_consumer_loop()  [MAIN LOOP - Runs Forever]                                                      │ │
│  │  ├─ BRPOP from Redis (blocking until message arrives)                                                 │ │
│  │  ├─ Call process_queue_item(payload_json)                                                            │ │
│  │  │                                                                                                     │ │
│  │  └─ process_queue_item() ─────────────────────────────────────────────────────────────────────────┐  │ │
│  │                                                                                                    │  │ │
│  │     STEP 1: Parse QueuePayload                                                                   │  │ │
│  │     ├─ JSON → QueuePayload (pydantic validation)                                                 │  │ │
│  │     └─ Extract: raw_document_id, source, content, namespace, ...                                 │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 2: Map to RawDocument                                                                   │  │ │
│  │     ├─ Call get_mapper(source) → [gmail.py, github.py, notion.py, custom.py]                  │  │ │
│  │     ├─ mapper.map(payload) → RawDocument {content, source, author, timestamp, metadata}         │  │ │
│  │     └─ Each mapper knows its source's JSON schema                                                │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 3: Normalise (8-Stage Pipeline)                                                        │  │ │
│  │     ├─ Call pipeline/normalizer.py: normalise(raw_doc)                                          │  │ │
│  │     ├─ 1. Encoding repair + Unicode NFC                                                         │  │ │
│  │     ├─ 2. OCR artifact correction (scanned docs)                                                │  │ │
│  │     ├─ 3. Temporal normalisation (date formats → ISO 8601)                                      │  │ │
│  │     ├─ 4. Text surface cleaning (whitespace, control chars)                                    │  │ │
│  │     ├─ 5. BM25 statistical weighting                                                           │  │ │
│  │     ├─ 6. Numerical/currency normalisation                                                     │  │ │
│  │     ├─ 7. Content hashing + MinHash signature                                                 │  │ │
│  │     └─ Output: NormalisedDocument {content, hash, minhash_sig, ...}                            │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 4: Scrub PII                                                                           │  │ │
│  │     ├─ Call pipeline/pii.py: scrub_pii(norm_doc)                                               │  │ │
│  │     ├─ Uses: spaCy NER + Microsoft Presidio                                                    │  │ │
│  │     ├─ Detects: emails, phones, SSNs, credit cards, secrets                                    │  │ │
│  │     ├─ Actions: redact or pseudonymise (reversible mapping)                                    │  │ │
│  │     └─ CRITICAL: No raw PII may reach Qdrant                                                   │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 5: Check for Duplicates                                                               │  │ │
│  │     ├─ Call pipeline/deduplicator.py: is_near_duplicate(norm_doc)                              │  │ │
│  │     ├─ MinHash LSH: Check signature against Redis index                                        │  │ │
│  │     ├─ If Jaccard >= 0.85 → SKIP document                                                      │  │ │
│  │     └─ Otherwise → Add to LSH index, continue                                                  │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 6: Chunk                                                                               │  │ │
│  │     ├─ Call pipeline/chunker.py: chunk(content)                                                │  │ │
│  │     ├─ Recursive splitter: 512-token windows with 102-token overlap                            │  │ │
│  │     ├─ Smart boundaries: paragraph > newline > sentence > comma > space                        │  │ │
│  │     ├─ Output: [ Chunk {text, index, offsets, parent_doc_id, ...}, ... ]                       │  │ │
│  │     └─ Chunks inherit parent metadata                                                          │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 7: Embed                                                                               │  │ │
│  │     ├─ Call pipeline/embedder.py: embed_chunks(chunks)                                         │  │ │
│  │     ├─ Model: all-MiniLM-L6-v2 (384-dim, loaded once per worker)                              │  │ │
│  │     ├─ Batch: 64 chunks at a time for efficiency                                               │  │ │
│  │     ├─ Normalise: L2 normalize all vectors                                                     │  │ │
│  │     └─ Output: [ (chunk, 384-dim vector), ... ]                                               │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 8: Upsert to Qdrant                                                                    │  │ │
│  │     ├─ Call db/qdrant_client.py: upsert_to_qdrant(vector, payload, namespace)                 │  │ │
│  │     ├─ Payload includes: text, source, author, timestamp, chunk_index, namespace, hash        │  │ │
│  │     ├─ SACRED: namespace field MUST flow through (RBAC boundary)                               │  │ │
│  │     └─ Qdrant stores: point {id, vector, payload} in collection "company_brain"               │  │ │
│  │                                                                                                    │  │ │
│  │     STEP 9: Confirm in Postgres                                                                │  │ │
│  │     ├─ Call db/postgres_client.py: update_document_status(doc_id, "PROCESSED")                │  │ │
│  │     ├─ Email.status: PENDING → PROCESSED (with timestamp)                                     │  │ │
│  │     └─ If ANY error in steps 2-8 → status = "FAILED" with error message                       │  │ │
│  │                                                                                                    │  │ │
│  │     Loop back to BRPOP (wait for next item)                                                     │  │ │
│  │                                                                                                    │  │ │

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                    COMPLETE DATA FLOW LOOP                                                     │
│                                                                                                                 │
│  1. SYNC (Frontend)                                                                                           │
│     User clicks "Sync Gmail"                                                                                  │
│       ↓                                                                                                        │
│     Fetch from Gmail API (20,000 recent emails)                                                              │
│       ↓                                                                                                        │
│     For each email: UPSERT to Postgres Email table (status=PENDING)                                          │
│       ↓                                                                                                        │
│     publishToQueue(): LPUSH QueuePayload to Redis                                                            │
│       ↓                                                                                                        │
│     Update Email.status = QUEUED                                                                             │
│       ↓                                                                                                        │
│     Return: { synced: 20000, queued: 20000, message: "..." }                                                │
│                                                                                                                 │
│  2. QUEUE (Redis)                                                                                             │
│     Items sit in company_brain:ingest list                                                                   │
│                                                                                                                 │
│  3. PROCESS (Python Worker)                                                                                   │
│     Worker BRPOP from queue (blocking)                                                                       │
│       ↓                                                                                                        │
│     Parse QueuePayload → RawDocument                                                                         │
│       ↓                                                                                                        │
│     Run 9-step pipeline: Map → Normalise → PII → Dedup → Chunk → Embed → Upsert → Confirm                 │
│       ↓                                                                                                        │
│     Each email → multiple 512-token chunks → multiple 384-dim vectors → Qdrant points                       │
│       ↓                                                                                                        │
│     Update Email.status = PROCESSED (with timestamp)                                                         │
│       ↓                                                                                                        │
│     Loop back to BRPOP                                                                                        │
│                                                                                                                 │
│  4. STORE (Qdrant + Postgres)                                                                                │
│     Qdrant: 384-dim vectors with payloads (text, source, author, chunk_index, namespace, ...)              │
│     Postgres: Document status = PROCESSED (with metadata)                                                   │
│                                                                                                                 │
│  5. MONITOR (Frontend - Polling)                                                                              │
│     PipelineMonitor polls GET /api/document/{docId}/status every 2 seconds                                 │
│       ↓                                                                                                        │
│     Shows: PENDING → QUEUED → PROCESSING → PROCESSED (green checkmark)                                      │
│       ↓                                                                                                        │
│     Once PROCESSED, search becomes available                                                                 │
│                                                                                                                 │
│  6. SEARCH (Frontend + Python)                                                                                │
│     User types: "What are our Q2 revenue trends?"                                                            │
│       ↓                                                                                                        │
