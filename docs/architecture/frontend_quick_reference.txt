KEY LAYERS
──────────────────────────────────────────────────────────────────────────────
1. PAGES (app/)         → URL routing, data fetching, layout composition
2. COMPONENTS (_comp/)  → Reusable UI, state, interactivity
3. LOGIC (lib/, types/) → Types, utilities, business logic
4. ACTIONS (actions/)   → Server actions for mutations


DATA FLOW (The Core Loop)
──────────────────────────────────────────────────────────────────────────────
User Action (click button)
    ↓
Client Component calls Server Action
    ↓
Server Action queries/mutates Prisma + calls API route
    ↓
Postgres/Redis/Qdrant updated
    ↓
Page revalidated (revalidatePath)
    ↓
Page re-renders with new data
    ↓
UI updates immediately

COMMON PATTERNS
──────────────────────────────────────────────────────────────────────────────

Creating a Workflow:
  User clicks "New Workflow"
    ↓ <CreateWorkflowDialog />
    ↓ Form submission → POST /api/workflows OR Server Action
    ↓ Insert Workflow row in Prisma
    ↓ Redirect to /connectors/{workflowId}

Saving Workflow Definition:
  User clicks "Save"
    ↓ <SaveBtn /> calls saveWorkflow(workflowId, flowDef)
    ↓ Server Action updates Workflow.definition
    ↓ revalidatePath() invalidates cache
    ↓ Toast: "Workflow saved ✓"

Syncing Data:
  User clicks "Sync" on Gmail node
    ↓ <GmailConnectButton /> calls POST /api/gmail/sync
    ↓ Route handler: fetch Gmail API, UPSERT Email rows, LPUSH Redis
    ↓ Return { synced: X, queued: Y }
    ↓ Toast: "Synced X emails"

Running Workflow:
  User clicks "Run"
    ↓ <RunBtn /> calls runWorkflow(workflowId)
    ↓ Server Action: create WorkflowExecution, queue all documents
    ↓ Redirect to /connectors/runs/{wId}/{eId}
    ↓ <PipelineMonitor /> polls status every 2 seconds
    ↓ Shows: PENDING → QUEUED → PROCESSED

Searching:
  User enters query
    ↓ <SearchResults /> POST /api/search
    ↓ Next.js route calls Python backend
    ↓ Python embeds query, searches Qdrant
    ↓ Returns [ { text, source, score }, ... ]
    ↓ Display results with badges


AUTHENTICATION & AUTHORIZATION
──────────────────────────────────────────────────────────────────────────────
Clerk handles login/session
  ├─ ClerkProvider in root layout
  ├─ middleware.ts checks auth before dashboard
  └─ auth() function returns { userId } in server code

Multi-tenant check:
  const { userId } = await auth()
  const workflow = await prisma.workflow.findUnique({
    where: { id: workflowId, userId }  // ← Prevents cross-user access
  })


COMPONENT PATTERNS
──────────────────────────────────────────────────────────────────────────────

Button → Server Action:
  <form action={createWorkflow}>
    <input name="name" />
    <button type="submit">Create</button>
  </form>

Polling (Status Updates):
  const { data: status } = useQuery({
    queryKey: ['document', docId, 'status'],
    queryFn: () => fetch(`/api/document/${docId}/status`).then(r => r.json()),
    refetchInterval: 2000  // 2 second polling
  })

OAuth Flow:
  User clicks <GmailConnectButton />
    → Redirect to /api/gmail/auth
    → Google OAuth → /api/gmail/callback
    → Insert GmailConnection
    → Redirect back to editor


API RESPONSE PATTERNS
──────────────────────────────────────────────────────────────────────────────

Success:
  { success: true, data: {...} }
  HTTP 200

Error:
  { error: "User-friendly message" }
  HTTP 400/401/403/404/500

Status Tracking:
  { id, source, status, errorMessage?, processedAt? }

Sync Response:
  { synced: int, queued: int, skipped: int, message: string }

Search Results:
  { results: [ { text, source, author, score }, ... ] }


DATABASE QUERIES
──────────────────────────────────────────────────────────────────────────────
Always import Prisma from lib/prisma.ts (singleton):
  import prisma from "@/lib/prisma"

Always filter by userId:
  WHERE { id: workflowId, userId }

Don't N+1:
  Use include/select to fetch related data
  prisma.workflow.findUnique({
    where: { id, userId },
    include: { workflowExecutions: true }
  })

Transactions:
  prisma.$transaction([ op1, op2, op3 ])

NEXT.JS SPECIFICS
──────────────────────────────────────────────────────────────────────────────
"use client" = Client Component (use hooks, setState)
"use server" = Server Action (mutations, DB access)

No directive = Server Component (default)
  Can: async, Prisma queries, secrets
  Cannot: hooks, event handlers

revalidatePath("/path") = Invalidate cache for this route
revalidateTag("tag-name") = Invalidate by tag (fine-grained)
generateStaticParams() = Generate static routes at build time

COMMON ISSUES
──────────────────────────────────────────────────────────────────────────────

"TypeError: Cannot read property 'userId' of undefined"
  ↳ Missing: const { userId } = await auth()
  ↳ Fix: Add auth check to server component/action

"Prisma client not found"
  ↳ Wrong: import { PrismaClient } from "@prisma/client"
  ↳ Right: import prisma from "@/lib/prisma"

"Styles not applying"
  ↳ Check: Is className spelled correctly?
  ↳ Check: Is Tailwind config correct? (tailwind.config.ts)

"OAuth callback fails"
  ↳ Check: GOOGLE_CLIENT_ID/SECRET in .env.local
  ↳ Check: Callback URL registered in Google Cloud Console
  ↳ Check: Redirect URL in app/api/gmail/callback matches config

"Can't access other users' data"
  ↳ Expected: { userId } filter prevents this
  ↳ This is correct behavior (multi-tenant)

NEXT STEP IF STUCK
──────────────────────────────────────────────────────────────────────────────
1. Check: Is this a server or client component?
   → No "use client" = server component (can use Prisma)
   → Has "use client" = client component (can use hooks)

2. Check: Is auth required?
   → const { userId } = await auth()
   → WHERE { userId } filter in Prisma queries

3. Check: Is it a mutation or read?
   → Mutation: Use Server Action or POST API route
   → Read: Use page component or GET API route

4. Check: Does data need real-time updates?
   → Yes: Use React Query with refetchInterval
   → No: Fetch once in server component

5. Check: Are you accessing another user's data?
   → Should fail (correct). Fix: Add userId to WHERE clause.
